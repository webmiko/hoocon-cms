## 4. Развитие сайта (продукт, UX, SEO, CMS)

### 4.1. Роль сайта

Понять «кто вы» → подобрать модель → скачать документ → оставить заявку.
ВК и Макс возвращают сюда или в заявку через менеджера. Сайт хранит **доказательства**
и инструмент подбора, а не конкурирует с соцсетями за развлекательный контент.

### 4.2. Структура и приоритетные страницы (первые 8–10 недель)

| Задача | Деталь |
|--------|--------|
| Связка каналов | В подвале и на `/company` / контактах: ВК (когда URL зафиксирован), бот и канал Макса |
| Команда | Блок на «О компании»: имя, роль, зона ответственности (без выдуманных должностей) |
| Российские объекты | 5–7 историй: тип здания, город, серия, задача; заказчик — только с разрешения |
| Вход замен | `/replacement` и статья `analog-belimo-hoocon` как **понятный вход**, не только фасет |
| Статьи подбора | Продолжить серию (момент, 24/230 В, управление, ОЗК/дым, приёмка документов) |
| Единый CTA | На ключевых экранах один следующий шаг: **подбор** или **запрос КП** |
| AIRVent 2027 | Новость с датами/павильоном; обновить номер стенда, когда выдадут организаторы |

### 4.3. Каталог, подбор, сравнение

| Компонент | Статус | Следующие шаги |
|-----------|--------|----------------|
| Квиз `#podbor` | В проде | P1: ближайший Nm при отсутствии на складе; CTA «готовый комплект» у кранов (`QUIZ_ANALOGS_PLAN.md`) |
| Belimo в квизе | Частично | P2: шаг/поле «замена Belimo» → `/replacement`, facet `analog` |
| `/compare` | MVP shipped (до 4 SKU) | Доработки: RFQ с несколькими артикулами, мобильная читаемость |
| Карточки SKU | ETL + Admin | Паспорта, фото из мануалов; не публиковать без согласованных остатков/фото |

### 4.4. Заявки и SLA

Формы: `rfq`, `consultation`, `replacement` (`/consultation`, `/replacement`).
Celery → SMTP; уведомления персоналу (в т.ч. Telegram staff).

**Блокер рекламы ВК:** заявка с сайта и из бота Макс **доходит до менеджера**.
Иначе сначала чинить приём, не бюджет.

### 4.5. SEO — технический фундамент (не дублировать `seo-url-migration.md`)

До масштаба контента — иначе хабы не индексируются. Контрольный чеклист:

| # | Работа | DoD |
|---|--------|-----|
| T1 | HTTPS | Валидный TLS, без mixed content |
| T2 | 301 с Tilda | `Redirect` + nginx; `scripts/check-url-inventory.sh` |
| T3 | `sitemap.xml` + `robots.txt` | Только canonical path |
| T4 | Индексируемый HTML | title, description, canonical, og в `spa_index_view` |
| T5 | JSON-LD | Organization, Product, Article, FAQPage, Breadcrumb — по типу URL |
| T6 | Метрика, Вебмастер, Search Console | Счётчики на проде |
| T7 | Архитектура кликов | Важные URL ≤ 3 кликов от `/` |
| T8 | KPI-запросы | Список §9; срез позиций раз в 2 недели |

Title/description: уникальные, ~50–60 / ~150–160; один H1; без «купить дёшево» в v1.
Не закупать ссылки; естественные упоминания (партнёры, соцсети).

### 4.6. SEO — три кластера KPI

1. Аналоги / замена Belimo — хаб, `/replacement`, P1-2.
2. Подбор (момент, 24/230, управление) — статьи P1, фасеты каталога.
3. Бренд HOOCON + серии — `/`, `/company`, `/zavod`, PDP, посадочные серий.

**Правило:** не публиковать непроверенные пары Belimo↔HOOCON (см. `data-quality-etl.md`).

### 4.7. Контент в CMS (статьи и новости)

**Общие правила:** термины Нм, В; «ориентир» vs точные ТТХ из SKU; внутренние ссылки
на каталог, FAQ, `/consultation`, `/replacement`; title/meta по `seo-meta-yandex-google.md`.

**Бэклог (сжато из плана статей):**

| Приоритет | Slug (примеры) | Назначение |
|-----------|----------------|------------|
| P1 | `podbor-privoda-po-momentu-i-ploshchadi`, `analog-belimo-hoocon`, `pitanie-24-ili-230-v`, `tipy-upravleniya-privodom`, `mu-mqu-hv-kogda-nuzhen-uskorennyy` | Решения на объекте |
| P2 | суффиксы D/A/S/T, fail-safe, CE/UL/EAC, комплект кран+привод | Меньше ошибок в спецификации |
| P3 | кейсы РФ, «как оформить заявку на КП» | Доверие (только подтверждённые факты) |

**Ритм публикации:** отложенный `published_at`; go-live → новость + опционально
анонс в соцсети (`article_go_live`, флаг `social_announce_on_publish` в SiteSettings).

**Workflow для редактора/разработчика:**

1. Fixture/HTML в `backend/content/fixtures/`, seed (`seed_site_content`, `seed_wiki` не путать).
2. Обложки WebP (светлая/тёмная при необходимости).
3. После публикации — проверить sitemap и анонс VK/MAX/Telegram в Admin.

### 4.8. Дизайн и публичный UI

Канон: `_docs/design-system.md` (локально), правило `frontend-public-ui.mdc`:
токены, CWV, accessibility, CSP. Не ослаблять CSP ради метрик.

## 5. Соцсети: ВК и Макс

### 5.1. Роли каналов

| Канал | Роль | Частота | Метрики |
|-------|------|---------|---------|
| Сайт | Штаб, доказательства, подбор | По мере релизов | Подбор, PDF, RFQ, брендовый поиск |
| ВК | Витрина, охват, **реклама** | 2–3 поста/нед | Переходы, заявки, CPL |
| Макс (канал) | Короткие новости | ~2 коротких/нед | Охват дочитывания (вторично) |
| Макс (бот) | Сервис, заявка | По запросу клиента | Старты, заявки из бота |

### 5.2. ВК — оформление и контент

- Название вроде «HOOCON — электроприводы ОВК»; описание, обложка в стиле сайта.
- Телефон, сайт, режим, ссылка на бот Макса; закреплённый пост-визитка.
- Живой ролик 1080×1920 — и оформление, и креатив рекламы.
- Посты: сильные материалы, не ежедневный шум.

**Инженерия (уже в репо):** `vk_setup_community`, `vk_setup_callback`,
`scripts/sync-vk-callback-env-to-vps.py`; публикация из Admin (`SocialPost`).

### 5.3. Макс — проверка бота (ноябрь 2026)

- `/start` — понятное меню без внутренних кодов.
- Заявка попадает к менеджеру, не теряется.
- Автоответ: пн–пт 9:30–17:30 (МСК), ответ до 2 рабочих часов.
- Одинаковые телефон, почта, гарантия 24 месяца, что на сайте.

Команды: `max_setup_bot`, `max_setup_channel`, `max_setup_webhook`.

### 5.4. Анонсы из CMS

При публикации статьи/новости — `social.services.announce_content` в включённые
каналы (Telegram/VK/MAX по SiteSettings). Текст: `social.compose.compose_announcement`
(до ~280 знаков excerpt + URL). Для ВК/Макс — тот же материал, что на сайте,
адаптированный короче; в Макс — прямая кнопка в бота.

### 5.5. Единый inbox (сайт + мессенджеры)

Виджет на сайте + ЛС TG/VK/MAX → Admin «Поддержка». Это **не** замена RFQ, а
уточнения и сервис. Deep links из виджета в мессенджеры. Расписание support:
согласовать с обещанием 9:30–17:30 и автоответом вне часов.

Детальная архитектура (webhooks, модели) — была в `plan-support-chat-social.md`;
код: `supportchat`, `social/webhooks.py`. Маркетинговые требования: те же слова о
гарантии и сроках, что в §3.

## 6. Контент-система и рубрики

Контент **берётся с сайта и из продаж**, затем адаптируется под канал.

| Рубрика | Источник | Где публикуем |
|---------|----------|----------------|
| Как подобрать | Статьи, FAQ | Сайт → ВК → коротко Макс |
| Конкретная замена Belimo | `/replacement`, подбор | Сайт, ВК (осторожно с формулировками) |
| Склад Москва / отгрузка РФ | Факты склада, без выдуманных остатков | Сайт, ВК, Макс |
| Объект / применение | Отгрузки, фото с разрешения | Сайт, ВК, кейс в статье |
| Документ недели | Паспорт, сертификат, CE/UL/EAC | Сайт, ВК, Макс |
| Человек из команды | Реальные сотрудники | Сайт, ВК |
| Выставка (AIRVent и др.) | Новости hoocon.ru, факт с площадки | Сайт, ВК, Макс — **без** CRM-скриптов посетителя |

**Ритм:** 2 поста ВК + 2 коротких публикации в канале Макса **каждую неделю**.
Раз в месяц — разбор или объект. Перед AIRVent — до 3 постов/нед без снижения
качества.

## 7. Реклама ВК и предпосылки

Запуск **только если:**

- Сообщество оформлено и связано с сайтом.
- Заявка с сайта и из бота доходит до менеджера.
- Тексты совпадают с тем, что продажи могут выполнить.

**Целевое действие:** подбор или запрос КП на hoocon.ru — не «вступить в сообщество».

**Таргет:** вентиляция, кондиционирование, ОВК, проектирование, снабжение, монтаж.
Гео: Москва и МО, затем города с реальными запросами.

**Контроль:** раз в 2 недели — заявки и стоимость заявки, не охваты.

Текст объявления — [приложение A](#приложение-a-текст-рекламы-вк-до-300-символов).
