# Функционал staff-админки

Канон для LMS-подобных и B2B CMS проектов. Стиль — в
[стиль-и-цвета.md](стиль-и-цвета.md).

---

## 1. Роль админки в архитектуре

```
nginx (prod) → Django (gunicorn)
                 ├─ Admin (staff write) ← этот стандарт
                 ├─ DRF public read API
                 ├─ services/ (бизнес-логика вне views/admin)
                 └─ Celery → SMTP / ETL
```

Правила:

- Публичный API — **read-only** (+ точечный POST заявок / leads).
- Запись доменных сущностей staff — через Admin (или staff API позже).
- Бизнес-правила — в `services/`, не дублировать в `save_model` без нужды.
- Side-effects (письмо, индекс) — `transaction.on_commit` + Celery.

## 2. ModelAdmin — обязательный каркас

Наследовать **`unfold.admin.ModelAdmin`**, не `django.contrib.admin`.

```python
from django.contrib import admin
from unfold.admin import ModelAdmin

from catalog.models import SKU


@admin.register(SKU)
class SKUAdmin(ModelAdmin):
    """Карточка SKU: список, поиск, фильтры, whitelist полей."""

    list_display = ("sku_code", "title", "category", "is_published", "updated_at")
    list_filter = ("is_published", "category")
    search_fields = ("sku_code", "title", "slug")
    prepopulated_fields = {"slug": ("title",)}
    readonly_fields = ("created_at", "updated_at")
    ordering = ("-updated_at",)
    list_per_page = 50
    show_full_result_count = False  # на больших таблицах
```

### Обязательные практики

| Практика | Зачем |
|----------|--------|
| Явный `list_display` / `search_fields` / `list_filter` | UX менеджера |
| `readonly_fields` для timestamps / computed | нет mass-overwrite |
| `fieldsets` с группами | длинные формы (SKU, User) |
| `raw_id_fields` / autocomplete на FK | N+1 и огромные select |
| Кастомная `ModelForm` при нетривиальной валидации | как в LMS/OB2 |
| `list_select_related` / `get_queryset` с prefetch | N+1 на changelist |
| Без голого `exclude = ()` «на всё» | mass assignment |

### Inlines

- Tabular/Stacked через Unfold inlines при связях 1:N (файлы SKU,
  атрибуты).
- Лимит строк; файл — size/type whitelist (PDF/изображения).

### Действия (actions)

- Только явные staff-safe операции (публикация, экспорт).
- Опасные — confirmation + лог; не удалять каскадом «втихую».

## 3. Типовые зоны SIDEBAR

Группировать по домену продукта, не по `app_label` вразнобой.

**B2B-каталог (Hoocon-like):**

1. Каталог — Category, Product, SKU, Attribute, ProductFile
2. Контент — Page, Article, News
3. Заявки — Lead / RFQ
4. SEO — Redirect
5. Настройки — SiteSettings (`show_prices_on_site`, контакты)
6. Пользователи — User / Group (только superuser / admin-группа)

**LMS / paywall:**

1. Контент — Post / Course / Lesson
2. Пользователи — User (phone/email), подписки
3. Биллинг — только если в scope (не тащить в B2B v1)
4. Системное — Celery/beat при необходимости через отдельные apps

Бейджи на пунктах (число новых заявок) — через callback Unfold,
без тяжёлых запросов на каждый request (кеш/короткий TTL).

## 4. Права и безопасность

См. также модуль `безопасность/` и проектный security-baseline.

| Контроль | Правило |
|----------|---------|
| AuthN | Session + CSRF; Admin login только HTTPS в prod |
| AuthZ | `is_staff`; object-level — только если появилась роль |
| Throttle | django-axes **или** rate limit на `/admin/login/` |
| Mass assignment | whitelist полей формы / fieldsets |
| Файлы | max size, MIME/extension allowlist, без path traversal |
| Цены (B2B) | хранятся; публичный JSON только при `show_prices=True` |
| Логи | без паролей и полного PII |
| Prod | опц. IP allowlist nginx на `/admin/` |
| robots | `Disallow: /admin/` |

Запрещено:

- открывать Admin анонимам;
- отдавать staff-write через публичный JWT в localStorage в v1;
- `DEBUG`-панель с данными prod.

## 5. Настройки сайта и флаги

Singleton / одна запись `SiteSettings` (или Constance):

- `show_prices_on_site` (B2B, default `False`);
- контакты, SLA ответа, feature flags без редеплоя кода.

В Admin: только staff; изменение флага — без правки сериализаторов.

---

## 6. Тесты (минимум)

- anon → login redirect / 403 на write;
- staff → changelist 200, create/update happy path;
- duplicate / validation errors на форме;
- throttle login (если включён);
- B2B: цена не в public API при `show_prices=False`;
- smoke UI не обязателен в CI; достаточно client/admin tests.

---

## 7. Анти-паттерны

- Wagtail «вместо» Admin для табличного каталога SKU;
- копирование Tilda/WordPress UX в Admin;
- фиолетовая/дефолтная палитра Unfold без привязки к бренду;
- dark-mode first для industrial B2B без запроса заказчика;
- бизнес-логика только в `admin.save_model` без сервиса;
- `print` в admin hooks — только `logger`.
