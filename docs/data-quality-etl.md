# Качество данных при переносе (Tilda → CMS)

Дата: 2026-07-19  
Принцип: **переносим номенклатуру и факты, не копируем ошибки UX/текста
и мусор платформы.** URL-slug из индекса сохраняем даже с опечаткой
(SEO); контент и мета — правим.

Связано: [seo-url-migration.md](seo-url-migration.md),
[market-analysis.md](market-analysis.md),
[tech-copy-belimo-ru.md](tech-copy-belimo-ru.md) — терминология ТТХ,
аудит `../hoocon/docs/АУДИТ_HOOCON_RU.md`.

---

## 1. Иерархия источников правды

| Приоритет | Источник | Что брать |
|-----------|----------|-----------|
| 1 | Структурированный каталог (`hoocon_catalog_api.json`, CSV) | Артикул, атрибуты, цены (в БД), uid |
| 2 | Карта URL / seed CSV | `slug`, 301 from_path |
| 3 | PDF / заводские datasheet | ТТХ при конфликте с HTML |
| 4 | HTML карточки Tilda | Описание — только после вычитки |
| 5 | Главная / «О компании» Tilda | **Не** копировать 1:1; переписать по прототипу |

При конфликте «красивый текст на Tilda» vs «число в PDF/API» —
побеждает **число из API/PDF**, текст правим вручную.

---

## 2. Что переносим как есть

- Номенклатура: все SKU каталога (~39).
- Технические атрибуты из API/фильтров (момент, напряжение, пружина…).
- Цены в БД (на сайте скрыты по флагу).
- **Path/slug** из sitemap (включая `privod-protivipozharniy-3nm`).
- Файлы PDF/изображения, если валидны (не битые, не placeholder).
- Полезный FAQ (SA≠DA, расчёт площади, момент) — как контент, с правкой
  формулировок при необходимости.

---

## 3. Что сознательно НЕ переносим

| С Tilda / старого UX | Почему | На новом |
|----------------------|--------|----------|
| Иконки Cart / Wishlist / Members | E-com без checkout; путаница | RFQ + опц. список запроса |
| Три H1 на главной | SEO-ошибка | Один H1 |
| Грамматика/корявые title («оригинальный…») | CTR/доверие | Новые title по шаблону |
| Caps-хаос H2, вода/клише | Аудит §5–6 | Тексты из прототипа / редактора |
| CN-телефон и @hoocon.com.cn в первом контакте | Шум для РФ B2B | В футере «завод» опционально; шапка — РФ |
| Стена текста «О компании», переводной слоган | Слабый E-E-A-T | Структура H2 + объекты РФ |
| Битые / pageID URL (`/page….html`) | Мусор индекса | 301 или 410 |
| Tilda Store chrome, popup, тяжёлые виджеты | CWV | Свой React |
| Непроверенные «аналоги Belimo» без ссылок | Риск ошибки инженеру | AnalogMap только после валидации |

Цены: **не** открываем автоматически, даже если аудит советовал для
конверсии — политика проекта: скрыты + флаг.

## 4. Валидация в ETL (обязательные гейты)

Пайплайн: extract → **normalize/validate** → load. Падающий ряд —
в quarantine CSV, не в prod без review.

### 4.1 SKU / атрибуты

- [ ] `sku_code` / артикул уникален, не пустой
- [ ] `slug` ∈ инвентарь SEO или seed BV; формат `[a-z0-9-]+`
- [ ] Момент (Н·м), напряжение, тип управления — в словаре Attribute
  (не свободная строка «24 В 100...240 В» без нормализации)
- [ ] Единицы: `Nm`, `V` — канон; «НМ»/«Нм»/«nm» → одно значение
- [ ] Категория назначена (воздух / ПБ / дым / кран)
- [ ] Цена: число ≥ 0 или null; не строки «по запросу» в numeric-поле

### 4.2 Контент

- [ ] Title ≤ ~60 символов, без явных опечаток (список stop-patterns)
- [ ] Один смысловой H1 на страницу (в шаблоне, не из сырого HTML)
- [ ] Description уникален; не копипаст соседних SKU
- [ ] HTML описаний: strip script/style; без Tilda-классов
- [ ] ТТХ/инструкции — терминология
  [tech-copy-belimo-ru.md](tech-copy-belimo-ru.md)
  (`В=` не `VDC`; IP = «степень защиты корпуса», не «класс»)
- [ ] Аналоги: только если есть запись AnalogMap; иначе блок скрыт

### 4.3 Медиа

- [ ] PDF открывается, size &gt; 0, MIME application/pdf
- [ ] Изображения: не 1×1 placeholder; разумный max size
- [ ] Имя файла без path traversal

### 4.4 После загрузки (smoke)

- [ ] `SKU.count ==` ожидаемому total каталога
- [ ] Каждый slug из sitemap §2.1 отдаёт 200 в CMS
- [ ] Каждый tproduct из seed → Redirect 301
- [ ] Выборка 5 карточек: ручная сверка ТТХ с PDF

## 5. Ручной review (человек, не только скрипт)

Перед cutover менеджер/редактор проходит:

1. Главная, `/catalog`, `/company`, `/gde-kupit` — тексты не «с Tilda as-is».
2. По одной карточке из каждой серии (HVA, DA, SA, BV…).
3. FAQ SA vs DA — формулировки безопасности не искажены.
4. Юр. страницы (`/oferta`, privacy) — актуальные редакции, не старый HTML.

Чеклист аудита «сейчас → должно быть» (§6 аудита) — **вход в контент
нового сайта**, а не задача «скопировать Tilda».

## 6. Роли в коде

| Артефакт | Назначение |
|----------|------------|
| `scripts/etl_hoocon_data.py` | Import + validate + quarantine |
| `scripts/export_tilda_redirects.py` | Актуальный sitemap-store → CSV |
| `catalog` Attribute dictionary | Нормализация фильтров |
| Admin | Правка title/description/атрибутов без деплоя |
| pytest | Гейты §4 на фикстурах + счётчик SKU |

Ошибки ETL логировать с `type(e).__name__`; не глотать ValidationError.
