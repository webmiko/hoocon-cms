## 0. Цель и граница

**Цель:** устойчивое попадание в **топ-5** Яндекса по коммерческим кластерам ниши
электроприводов ОВК / аналогов Belimo — не «все запросы мира».

**Три кластера KPI:**

1. аналоги / замена Belimo;
2. подбор электропривода (момент · 24/230 · управление);
3. бренд Hoocon + серии (OEM-доверие).

**Не цель v1:** корзина и цена в сниппете как у дилеров; оплата.  
Ставка аудита: **подбор + PDF + RFQ + бренд OEM**.

**KPI:** канон запросов — §9.1 (22 фразы); **Базу** позиций проставить на 0–14 дн.

| Метрика | Как |
|---------|-----|
| Позиции топ-5 | срез по §9.1 раз в 2 недели |
| Органика | Метрика: визиты / цели с поиска |
| RFQ с органики | доля заявок `/consultation` · `/replacement` с organic |
| Индекс | Яндекс.Вебмастер + Search Console: хабы, статьи P1, sitemap SKU |

## 2. Карта кластеров → типы URL

Не плодить страницы «под каждый ключ». Один **тип URL** закрывает кластер.

| Кластер | Типы URL | Примеры запросов (ориентир) |
|---------|----------|-----------------------------|
| 1. Belimo / замена | хаб «аналоги»; `/replacement`; статья P1-2 | аналоги Belimo, замена Belimo на Hoocon |
| 2. Подбор | статьи P1-1…P1-5; FAQ; `/catalog/…` с фасетами | подбор привода по моменту, 24 или 230 В, типы управления |
| 3. Бренд / серии | `/`, company/zavod, спецификация, PDP, посадочные серий | hoocon электропривод, серия DA/SA, привод ОЗК |

Канон формулировок и частотности — в ядре
`../hoocon/docs/SEO_ЗАПРОСЫ_100_КЛЮЧЕВЫХ.md` (часть A = уже на тексте продакшена;
кластеры под новые посадочные — не публиковать ключ без текста на URL).

**Правило title/meta (БЗ §8 + локальный канон):**  
[seo-meta-yandex-google.md](seo-meta-yandex-google.md) — уникальные title (~50–60) и
description (~150–160); ключ естественно в title/H1/первом абзаце; польза инженеру
первой, бренд коротко; без «купить дёшево» в v1. Один **H1** на URL ([06_SEO][kb-seo-06]).

**Контент (БЗ §6):** сначала польза и факты (people-first), затем ключи/LSI без переспама;
на информационных блоках — короткий прямой ответ в начале секции (сниппеты / голосовой поиск).
Объём-ориентир БЗ: коммерческая посадочная ~2–5 тыс. знаков; статья-гид ~5–15 тыс.
(точные ТТХ — только из SKU/паспорта, как в плане статей).

## 3. Стыковка со планом статей

Бэклог статей **не дублируем**. SERP использует Iter из
[plan-articles-selection-guides.md](plan-articles-selection-guides.md):

| Окно SERP | Статьи (из плана) | Отдельно от «гида» |
|-----------|-------------------|---------------------|
| 14–45 дн. | Iter A: P1-1 → P1-4 → P1-3 | Хаб «аналоги Belimo»: метод + форма `/replacement`, **без** таблицы кроссов до валидации AnalogMap |
| 45–75 дн. | Iter B: P1-5 → P1-2 | Посадочные серий + перелинковка статья ↔ каталог ↔ RFQ |
| 75–90 дн. | P2 по готовности; P3 только с фактами | Кейсы OEM / «где купить» |

Запрет как в P1-2 и DoD статей: непроверенные пары Belimo↔Hoocon не публиковать
([data-quality-etl.md](data-quality-etl.md)).

Матрица внутренних ссылок P1 — §3 плана статей; для SERP дополнительно:

```text
хаб Belimo ──► /replacement, P1-2, спецификация, каталог
P1-1…P1-5 ──► /catalog/{facet}, /faq#…, /consultation
серия / PDP ──► PDF, RFQ, соседние статьи подбора
все коммерческие URL ──► CTA RFQ (SLA ≤ 2 ч)
```

## 4. Технический фундамент (блокер топа)

До масштаба контента — иначе хабы не индексируются.  
Порядок как в БЗ (этап SEO/тех → контент): сначала индексация SPA и cutover,
потом объём текстов. Cutover и 301: [seo-url-migration.md](seo-url-migration.md).  
Индексация React: [SEO-индексация-SPA.md][kb-seo-spa].

**Программа минимум БЗ (§8.6 / 06_SEO):** Яндекс.Вебмастер + Google Search Console;
Яндекс.Метрика (+ GA4 по желанию); естественные упоминания (партнёры, соцсети) —
**без закупки ссылок** (риск санкций, БЗ §7.3).

| # | Работа | DoD (БЗ + репо) |
|---|--------|-----------------|
| T1 | HTTPS / TLS на проде | сертификат валиден; без mixed content |
| T2 | Инвентарь 301 Tilda → CMS | Redirect / nginx; выборочный 200/301; без trailing-slash дублей |
| T3 | `sitemap.xml` + `robots.txt` | только canonical path; Disallow служебного; SC/Вебмастер без массовых ошибок |
| T4 | Индексable HTML | title, description, canonical, og в **исходном** HTML (`spa_index_view`); не только client |
| T5 | JSON-LD | Organization / Product (PDP) / Article / FAQPage / BreadcrumbList по типу URL; валидация Rich Results; без fake AggregateRating |
| T6 | Метрика + Вебмастер + SC | счётчик на проде; права в Яндекс.Вебмастер и Search Console |
| T7 | Архитектура кликов | важные URL ≤ 3 кликов от `/`; breadcrumbs на вложенных |
| T8 | Список KPI-запросов | §9.1 готов; колонка «База» (позиции) проставлена |

Срок блока: **0–14 дней** (как в аудите).  
CWV / Lighthouse — не раздувать этот план; держать в CI/релизах публичного UI
(золотое правило 12 / frontend), иначе топ по контенту упрётся в скорость.

## 5. Доверие OEM (E-E-A-T)

Дилеры выигрывают скоростью покупки; OEM выигрывает, когда инженер **верит заводу**.  
В терминах БЗ §6 / §8 — это **E-E-A-T** (опыт, экспертность, авторитет, надёжность):
факты, источники, конкретные объекты — не общие прилагательные.

| Тема | Куда | Ограничение |
|------|------|-------------|
| Завод / производство | `/zavod` · company | факты, не общие слова |
| Объекты / кейсы | P3-3, посадочные | только подтверждённые маркетингом/ПТО |
| Сертификаты | PDP / документы | без ложных сканов |
| Спецификация серий | уже на сайте | ссылки из хабов и P1 |
| Юр. прозрачность | реквизиты, политика | сигналы Trust (БЗ) |

## 6. Коммерция без корзины

| Элемент | Зачем |
|---------|--------|
| CTA «Заявка» / консультация | `/consultation` с каждой статьи и хаба |
| Замена Belimo | `/replacement` с чеклистом осей ТТХ |
| «Где купить» | страница/блок дистрибуции (75–90 дн.) |
| SLA RFQ ≤ 2 ч | обещание только если процесс реально держит |

Не обещать наличие/цену в сниппете как у e-com дилеров, пока нет честной витрины остатков
и политики публикации.

## 7. Дорожная карта 90 дней

```text
0–14 дн.   T1–T8: TLS, 301, sitemap/robots, SSR head, JSON-LD, Метрика/Вебмастер/SC, KPI-список
14–45 дн.  Iter A статей + хаб «аналоги Belimo» (метод + форма, без ложных кроссов)
45–75 дн.  Iter B + посадочные серий + перелинковка статья ↔ каталог ↔ RFQ
75–90 дн.  доказательства OEM (E-E-A-T) + «где купить» + разбор позиций vs топ-5
```

Параллельно каждые **2 недели:** срез позиций по KPI-списку; правки title/внутренних
ссылок по проседающим URL — не новый объём статей «наугад».

## 8. Анти-дилер / анти-риск

1. Не копировать модель «цена в сниппете любой ценой» — это чужая экономика.  
2. Не публиковать матрицу Belimo↔Hoocon без валидации.  
3. Не раздувать дубли посадочных под одну интенцию (один хаб / одна P1 на интенцию).  
4. Не обещать SLA RFQ и сертификаты без операционного покрытия.  
5. Не закупать ссылки (БЗ §7.3); только естественные упоминания / партнёры.  
6. Не подменять SSR-meta клиентским `useRouteSeo` без серверного head (БЗ SPA-SEO).  
7. Измерять регулярно; иначе «топ-5» останется лозунгом аудита.

## 10. Правила использования ключей в тексте

Канон: БЗ [06_SEO §7.2][kb-seo-06], [§6][kb-web-copy], [seo-meta-yandex-google.md](seo-meta-yandex-google.md),
[tech-copy-belimo-ru.md](tech-copy-belimo-ru.md).

### 10.1. Порядок работы (обязательно)

1. Польза инженеру и проверенные факты (план статей §0–§2).  
2. Выбрать **1 primary** + 2–4 secondary/LSI из §9.2.  
3. Title / H1 / первый абзац / description.  
4. Тело: разбавленные вхождения + LSI; без переспама.  
5. Чеклист БЗ §6.5 + DoD статьи.

### 10.2. Куда ставить

| Место | Правило |
|-------|---------|
| `<title>` | Primary ближе к началу; ≤~50–60 с брендом; уникален на URL |
| H1 | Один на страницу; primary естественно (не обязан = title) |
| Первый абзац / hero-dek | Прямой ответ на интент + 1× primary или близкая форма |
| H2 / H3 | Secondary и вопросы (для сниппетов / FAQ) |
| `meta description` | Смысл + CTA (КП / PDF); ключ без спама; ~140–160 |
| Alt картинок | По делу, не список ключей |
| URL / slug | Читаемый ЧПУ; не набивать всеми ключами |

### 10.3. Как вставлять (типы вхождений)

| Тип | Как | Частота |
|-----|-----|---------|
| Прямое | Точная или почти точная фраза primary | **1×** в H1 **или** первом абзаце (достаточно одного сильного места) |
| Разбавленное | Те же слова в другом порядке / падеже | Основной объём в теле |
| LSI | Синонимы и сопутствующие (момент↔Нм, заслонка↔клапан ОВК, Belimo↔белимо) | Много, по смыслу |
| Кириллица Belimo | На хабе/P1-2 явно «белимо» рядом с Belimo | Закрывает №2, №6 |

### 10.4. Ориентиры плотности (БЗ, не догма)

- Плотность основного ключа ~**0,5–2,5%**; классическая «тошнота» ~3–5% (не >7%).  
- Вода ~15–30% — норма для читаемого текста.  
- Объём: статья-гид ориентир **5–15 тыс.** знаков; не раздувать водой ради ключей.

### 10.5. Запрещено

- Набивка primary в каждом абзаце; Caps Lock; «лучший №1»; кликбейт.  
- Ключ ради ключа без факта (особенно Belimo-кроссы без валидации).  
- Подмена терминов tech-copy («плавное» вместо пропорционального; Н·м).  
- Primary «купить/цена» в статье-гиде P1 как главный месседж (RFQ / метод выбора).  
- Публикация фразы из части B ядра, пока её **нет в тексте** целевого URL.

### 10.6. Мини-DoD SEO на статью (добавка к DoD плана статей)

- [ ] Primary из §9.2 прописан в брифе статьи до написания.  
- [ ] Primary в H1 или первом абзаце; secondary в ≥1 H2 или теле.  
- [ ] Title и description уникальны; ключ в title без спама.  
- [ ] Ответ на интент в первых 2–3 абзацах (сниппет).  
- [ ] ≥3 внутренних ссылки по матрице P1 / SERP.  
- [ ] Нет непроверенных Belimo↔Hoocon таблиц.
