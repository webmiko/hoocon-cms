# SEO: title, description и сниппеты (Google + Яндекс)

Дата: 2026-07-19  
Опора: внутренняя база знаний (SEO SPA / индексация) и канон URL —
[seo-url-migration.md](seo-url-migration.md).

Для ИИ: при правке `<title>` / `meta description` / `Seo` / `spa_index_view`
сверяйся с этим файлом. H1 на странице **не обязан** совпадать с title
(на PDP H1 полный, title — короткий сниппет).

---

## 1. Жёсткие лимиты нет, ориентиры сниппета — да

Ни Google, ни Яндекс не режут ранжирование за длину title/description.
Обрезается **отображение** в выдаче (пиксели / ширина блока).

| Элемент | Ориентир (символы) | Практика 2025–2026 |
|---------|-------------------|---------------------|
| `<title>` | **50–60** (полный, с брендом) | Google ~580–600 px desktop; кириллица короче латиницы |
| `meta description` | **140–160** | Desktop ~920 px; mobile короче; часто **переписывают** |
| H1 | Без лимита сниппета | Один на страницу; ключ естественно |

Правила написания (оба поиска):

1. **Уникальность** title и description на каждый индексируемый URL.
2. **Ключ в начале** title (артикул / тип продукта / интент).
3. Без спама ключей, Caps Lock, «лучший№1», кликбейта.
4. Description — одно-два предложения + смысл CTA («запрос КП»,
   «паспорт PDF»), не вода.
5. Canonical без trailing slash; OG/Twitter = тем же title/description.
6. Клиентский Helmet **не заменяет** server-side head (краул Google/Яндекс).

### Отличия Яндекс ↔ Google (важно для РФ B2B)

| Тема | Яндекс | Google |
|------|--------|--------|
| Сниппет | Чаще берёт `description`, чувствителен к **дублям** title | Часто **переписывает** title/desc под запрос |
| Коммерция | Сильнее коммерческие факторы, регион, контакты/оферта | Product + Organization JSON-LD, CWV |
| Перепись | Меньше «креативной» переписи title, чем у Google | Rewrites обычны — пиши ясный title «на случай» |
| Вебмастер | Яндекс.Вебмастер + Метрика | Search Console (+ GA только после consent) |

Для Hoocon: регион РФ, телефоны/реквизиты, `/oferta`, `/kontakty`,
партнёры `/gde-kupit` — усиливают доверие в Яндексе; JSON-LD Product
без фейкового AggregateRating.

## 2. Шаблоны Hoocon

| Тип URL | Title (цель ≤60 с брендом) | Description (≤160) |
|---------|----------------------------|---------------------|
| Главная | Ключ + бренд уже в строке (не дублировать `— Hoocon`) | УТП + каталог/КП |
| Каталог / статьи | Короткий раздел + `— Hoocon` | Что найдёт пользователь |
| **PDP SKU** | `{артикул} — {напряжение} — Hoocon` (без Нм: момент уже в артикуле и ТТХ) | `{артикул}: электропривод ОВК. Паспорт PDF, запрос КП.` |
| Статья / новость | Заголовок обрезать до ~50 до суффикса бренда | Excerpt / первый абзац ≤160 |

**Нельзя для PDP title:** полный `sku.name` + «арт.» + бренд
(получается 80–150+ символов — в выдаче обрежется до артикула без пользы).

H1 на PDP — полный человекочитаемый `name` (после очистки «Нет»→SPDT).

## Аудит 2026-07-19

| Зона | Было | Статус |
|------|------|--------|
| Статические title | Большинство ≤60 | OK (главная 59) |
| Главная description | **161** символ | Исправлено ≤160 |
| PDP title (182 SKU) | **все >70**, 146 >90 | Шаблон → артикул + ТТХ |
| PDP description | Cap 160 в коде; сырой name в fallback | Короткий шаблон |
| Article/News title | `max_len=120` + бренд | Срезать до ~50 до бренда |
| noindex | `/search`, leads | OK |
| Server + client head | Двухслойно | OK по архитектуре БЗ |

Код: `config/seo/head.py`, `routes.py`, `frontend/src/components/Seo.tsx`,
хелперы длины — `config/seo/meta_text.py`.

## 4. Чеклист перед публикацией URL

- [ ] `curl -s URL | grep -E '<title>|meta name="description"|canonical'`
- [ ] Title ≤ ~60; description 120–160; уникальны
- [ ] Ключ/артикул в первых ~40 символах title
- [ ] Один H1; не noindex на коммерческой странице
- [ ] JSON-LD валиден (Rich Results / Яндекс валидатор)
- [ ] Нет цены в HTML при `show_prices_on_site=False`
