# План: личный кабинет клиента (обращения и КП)

Дата: 2026-07-26  
Статус: **согласовано в плане**; код — **после** регистрации/входа  
Цель: кабинет на сайте, где клиент видит **свои** обращения, товары с
запросом КП и **статус обработки**.

Связь: [plan-client-auth.md](plan-client-auth.md) (обязательный гейт);
CRM Lead / Activity; позже — [plan-support-chat-social.md](plan-support-chat-social.md)
(диалоги в «Обращениях»).

**Не путать** с «ЛК дилера с остатками» (вне scope v1 и этого плана): здесь
нет витрины остатков/цен для дилеров — только заявки и статусы своего
аккаунта.

Очередность крупных обновлений после MVP: см. [ПЛАН-ПРОЕКТА.md](../ПЛАН-ПРОЕКТА.md)
§6 «Очередь крупных обновлений» — ЛК идёт **сразу после** auth (A/B, опц. C).

## 1. Продуктовое решение

Страницы (черновик URL): `/account` или `/lk` (ЧПУ зафиксировать при UX).

| Блок | Содержание |
|------|------------|
| **Мои запросы КП** | Список Lead с типом RFQ / консультация / замена; связанные SKU/продукты; дата; **статус обработки** (как в Admin: новая / в работе / закрыта — публичные лейблы без внутренних полей staff) |
| **Обращения** | Заявки с форм + (когда будет supportchat) диалоги виджета/мессенджеров, привязанные к аккаунту |
| **Профиль** | Email, режим входа (пароль / OTP / Яндекс), выход; без смены чужих данных |

Клиент видит **только свои** записи (фильтр по `user` / email / `Client` owner).
Цены в ЛК — по тому же флагу `show_prices`, что и на сайте (не обход).

---

## 2. Модель / API (черновик)

- Привязка Lead → client account при логине или при создании Lead
  (если уже авторизован — писать `created_by` / `client_user_id`).
- Backfill: Lead с тем же email, что у аккаунта → показать в «Мои КП»
  (явное правило + тест на IDOR: чужой email не подтянуть).
- `GET /api/account/leads/` — paginated, только свои; поля: id, type, status
  label, created_at, sku list (code, name, url), без PII менеджера.
- `GET /api/account/leads/<id>/` — detail своей заявки; 404 чужой (не 403 с
  утечкой существования — по политике проекта).
- (фаза 2) `GET /api/account/conversations/` — свои диалоги supportchat.

Статусы: маппинг Admin → клиентские формулировки (напр. «Принята»,
«В работе», «Закрыта»); не светить внутренние assignee notes.

---

## 3. UX

- Один `h1` («Личный кабинет»); вкладки или секции: КП | Обращения | Профиль.
- Empty state: «Пока нет запросов» + CTA в каталог.
- Mobile: список карточек; desktop — таблица/список.
- Ссылка в шапке: «Войти» → после входа «Кабинет».

---

## 4. Безопасность

- AuthN обязателен; AuthZ по владельцу (IDOR-тесты).
- Нет mass assignment статуса клиентом (статус только staff/CRM).
- Throttle на list API; пагинация.
- Логи без полного телефона/тела заявки.

---

## 5. Итерации

### Фаза 1 — КП и статусы (первый ship ЛК)

- [ ] Привязка Lead ↔ user/Client; backfill по email
- [ ] API list/detail своих Lead + публичные status labels
- [ ] SPA `/account` (или выбранный ЧПУ): список КП + статусы + ссылки на SKU
- [ ] Тесты: happy path, чужой Lead → 404, anon → 401/redirect login

### Фаза 2 — обращения (после supportchat)

- [ ] Список своих диалогов / сообщений из виджета (+ каналы, если привязаны)
- [ ] Статус «ожидает ответа» / «отвечено» по непрочитанным

### Фаза 3 (опц., не блокер)

- [ ] Уведомление на email при смене статуса Lead
- [ ] Повторный запрос КП с предзаполнением из старой заявки

---

## 6. Критерии приёмки (фаза 1)

1. Авторизованный клиент видит только свои КП и товары из заявки.
2. Статус обработки отображается и совпадает с Admin (по маппингу лейблов).
3. Anon и чужой id — без утечки данных.
4. Нет корзины, оплаты, остатков дилера.
